> **发布主题：云端脚本引擎与多课表全面升级**
> v1.0.6.0 是一次覆盖导入能力、数据模型、数据库安全、课程提醒和 Android 平台适配的重大更新。它让教务系统页面变化后的适配可以更快交付，也让用户能够在同一设备上安全管理多套彼此独立的课表。

## 2. 更新亮点

### 2.1 重大更新：云端脚本引擎

教务系统经常会调整页面结构，以往这类变化通常需要等待整个应用发布新版本才能修复。本版本建立了可独立更新的导入脚本体系：应用会根据学校和教务系统选择合适的规则，在完成完整性与签名校验后启用新脚本。脚本发布与应用发布由此解耦，常见的页面适配问题可以更快恢复。

这套能力不仅是“从网络下载一段脚本”，还包含完整的安全与回退机制：

- **统一客户端执行协议**：Android 端内置 `script_host.js`，为应用内置脚本与远程脚本提供一致的输入、输出、错误和能力约束。
- **按场景选择解析器**：脚本清单与 `ParserSelectionPolicy` 共同决定使用哪个解析器；服务端不会接收或决定本地课表 ID。
- **可信更新**：下载内容经过哈希与 RSA-SHA256 签名校验，新版本先写入不可变暂存区；验证成功后再原子激活，失败时隔离候选并继续使用上一个可用版本。
- **故障隔离**：脚本在独立的 `:script_runtime` 进程中运行，并限制输入、输出、运行时间和资源占用。某条规则超时、异常或陷入循环时，只终止这次隔离执行，不拖垮主应用，也不影响其他规则。
- **灰度与回滚**：脚本注册表支持版本、灰度、kill switch 和回滚；自愈结果先成为待发布候选，不会未经审核直接覆盖全部用户的稳定脚本。
- **可诊断的失败**：解析结果会记录来源、版本、失败阶段和丢弃统计，帮助判断问题来自页面变化、脚本规则还是输入数据。

当现有规则无法识别新学校或变化后的页面时，应用可以在**用户明确同意**后提交诊断样本：

- 默认只上传经过现有脱敏器处理的页面内容；原始教务 HTML 不会在后台自动上传。
- 服务端只接受带有效同意信息且哈希匹配的脱敏样本，并通过会话标识跟踪同一次问题。
- 云端会对问题分类、合并重复问题，并使用基线、候选与回归样本验证修复脚本。
- 通过验证的候选仍需管理员审核后才能进入 canary 或 active 渠道，并保留审计与回滚记录。
- 该机制旨在缩短适配周期，但不承诺所有学校都能自动修复成功；无网络、用户不同意上传、样本不足或模型不可用时，仍保留本地解析和明确的失败提示。

### 2.2 多课表管理

本版本新增完整的多课表切换能力，适合同时管理不同学期、校区、培养方案或多个身份的课程：

- 支持新建空课表、新建课表并创建首个学期，以及完整复制当前课表。
- 支持在设置页切换、重命名和删除课表；系统始终至少保留一套课表。
- 每套课表独立保存学期、课程、导入来源、教务账号和自动更新绑定。
- 复制课表时会生成新的课表、学期、课程和凭据记录，复制后两套数据可独立修改。
- 普通导入默认写入当前课表；覆盖导入只清理明确选择的目标学期，不再全局删除其他课表数据。
- 自动更新固定绑定到具体课表和学期，即使更新过程中切换当前课表，也不会把结果写错位置。
- Widget、课程提醒、自动静音和课程通知只跟随当前课表；旧课表的迟到广播会经过归属校验并被忽略。

从 v1.0.5.1 升级时，Room 数据库会从 v5 迁移到 v6。迁移会创建“默认课表”，把原有学期与课程归入其中，并保留既有课程内容；这不是清空后重建数据库。

### 2.3 数据库加密与恢复

本版本把数据库安全打开、明文数据库迁移和故障恢复整合为同一套启动流程：

- 新数据库使用 SQLCipher 加密；已有明文数据库会通过临时数据库导出、完整性检查和原子替换完成加密迁移。
- 数据库文件存在但密钥缺失、失效，或数据库无法通过完整性检查时，应用进入专用恢复页，不会静默创建新库覆盖旧数据。
- 恢复页支持从应用备份文件或 WebDAV 恢复；只有用户明确确认放弃不可访问数据后，才允许创建新的空数据库。
- 恢复写入先在暂存数据库中完成，校验通过后再换入正式文件，降低恢复中断导致二次损坏的风险。
- Android 系统云备份继续关闭，并对设备间直传采用默认拒绝策略；换机请使用 Dawn Course 自身的本地备份或 WebDAV。

恢复机制的目标是保护原文件并从有效备份恢复，它不能保证修复任意损坏、密钥永久丢失且没有备份的数据库。升级前仍建议先导出一份可验证的应用备份。

### 2.4 导入兼容性改进

课程解析在本版本中完成了多轮兼容性修复：

- 修复升级后历史重复课程记录被同时送入布局、导致同一课程显示为多张窄卡的问题；修复仅收敛显示输入，不删除或改写用户课程数据，真正不同的同时段课程仍会并排显示。
- 修复“仅上一周”的课程可能被忽略或显示错误的问题。
- 支持更多单双周写法，包括前置标记、分隔符写法和括号内带“周”的表达。
- 改进整体括号周次、每段独立“周”后缀以及无冒号周数标签的解析。
- 正确处理方括号节次后缀，并对越界周次执行安全限制。
- 跨解析器累计保留丢弃诊断，便于发现部分课程被遗漏的具体原因。
- 登录凭据注入统一经过 JavaScript 字符串转义，覆盖引号、反斜杠、换行和 Unicode 行分隔符等边界输入。

### 2.5 提醒、自动静音与桌面课表小组件

课程相关的系统触发器从“整批取消后重建”调整为按稳定身份增量对账：

- 触发器身份包含课表、课程、发生日期与类型，消除大课程 ID、跨日期和多课表之间的碰撞。
- 开机、应用升级、系统时间或时区变化后会重新协调当天触发器。
- 用户可感知的提醒仍优先使用精确闹钟；权限或系统条件不允许时会降级，并由后台工作补充遗漏修复。
- 自动静音新增恢复责任记录与重试路径，切换课表时也不会遗失已经创建的恢复责任。
- 移除依赖每分钟轮询的常驻前台服务，课程通知改由课程边界、日期与设置变化驱动刷新。
- Widget 使用当前课表的时间线，在午夜、课程边界、系统恢复和课表切换时刷新；下一门课程更新另有 WorkManager 后备任务。

受 Android 省电策略和精确闹钟权限影响，降级路径不能承诺所有设备都绝对准点。若提醒对你非常重要，请允许精确闹钟并将应用加入厂商系统的后台运行白名单。

### 2.6 启动稳定性与 Android 16 适配

- 修复 App Startup 与 WorkManager 初始化竞态导致的冷启动白屏或闪退。
- 后台 Widget 协程异常不再升级为整个应用进程崩溃。
- 新增本地崩溃记录与可见提示，便于用户在不上传隐私数据的情况下保留故障线索。
- 构建工具链升级为 AGP 9.3.1、Gradle 9.5.0、Kotlin 2.2.10，`compileSdk` 37、`targetSdk` 36。
- 所有 Android 模块统一使用 JVM 17 与 Kotlin Compose plugin，并统一 Compose 稳定性配置。
- QuickJS 与 SQLCipher 随通用 APK 提供四种 ABI，构建过程加入 16 KB native page alignment、APK 大小预算与安装前检查。

### 2.7 应用内更新与下载

- 检查更新优先访问 Dawn 自建 HTTP 服务；主节点不可用时依次切换 GitHub Raw、GitHub API 与 jsDelivr，单个节点故障不再直接导致检查失败。
- APK 在应用内下载到私有缓存，并使用固定的 `.apk` 文件名，不依赖服务器返回的 MIME 类型，因此 Gitee 返回 `application/zip` 时也不会保存成 `.apk.zip`。
- 下载完成后校验文件头、SHA-256、包名、版本号与签名证书，通过后再打开系统安装页；校验失败时删除临时文件并明确提示原因。
- 自建更新元数据入口使用 HTTP，内容存在被中间网络篡改或重放的风险；APK 下载仍使用 HTTPS，并由哈希、包名、版本与签名校验共同保护安装边界。

## 3. 技术实现摘要

### 3.1 数据与领域边界

- Room v6 建立 `TimetableProfile -> Semester -> Course` 关系；`activeProfileId` 作为界面选择保存在 DataStore，各课表自己的活动学期保存在 Room。
- 教务凭据按 Profile UUID 使用独立加密文件保存；复制课表时重新加密到目标文件，删除课表时清理对应凭据。
- 导入提交通过明确的目标课表/学期和单次 Room 事务完成；自动更新使用固定的 `profileId + semesterId + sourceBindingId` 绑定。
- `CourseEntity.originId` 新增索引，改善拆分课程、调课和撤销路径中的关联查询。
- Room schema 已开启导出，v5 与 v6 schema 随代码保存；运行时不再使用 `fallbackToDestructiveMigration()`。

### 3.2 脚本同步与隔离运行时

- `ScriptSyncRepositoryImpl` 负责清单拉取、缓存、签名/哈希校验、暂存、原子激活与回退。
- `ParserSelectionPolicy` 保持纯选择逻辑，按学校、教务系统和脚本清单选择解析器。
- `QuickJsRuntimeAdapter` 隔离具体 QuickJS wrapper；运行服务通过 AIDL 与主进程通信。
- `ScriptRuntimeLimits`、执行闸门和超时终止共同限制脚本输入、输出与运行资源。
- 云端修复平台负责样本分类、问题归并、候选脚本生成与回放验证；Android 客户端仍掌握上传同意、脚本校验和本地数据落库权。

### 3.3 调度与后台任务

- `TriggerKey`、`ScheduledTriggerRegistry` 与 `TriggerReconciler` 共同实现 Desired/Scheduled 的 add、keep、remove 差异对账。
- `DailySchedulerWorker`、`WebDavAutoSyncWorker` 与 `WidgetUpdateWorker` 统一使用 Hilt Worker 注入。
- `SystemScheduleReceiver` 处理开机、应用替换、时间和时区变化，只提交唯一的恢复/对账工作。
- `PersistentNotificationPlanResolver` 与边界刷新调度器替代长期运行的 `dataSync` 前台服务。

### 3.4 构建与质量门禁

- 新增 Macrobenchmark 与 Baseline Profile，覆盖冷启动、今日/周课表、快速切周、长列表滚动、Widget 数据构建和 Room 冷查询等旅程。
- `releaseSmoke` 使用与正式 release 相同的 R8、资源压缩和 native packaging，并校验 Baseline Profile、四 ABI 原生库、16 KB 对齐与 APK 大小预算。
- CI 拆分并行任务，加入 Android SDK、Gradle 配置缓存和 CodeQL 构建检查，缩短反馈时间并保留安全门禁。

### 3.5 主要依赖与平台版本

- Android Gradle Plugin 9.3.1
- Gradle 9.5.0
- Kotlin 2.2.10
- Compose BOM 2026.08.00
- Room 2.8.4
- SQLCipher 4.18.0
- QuickJS wrapper 3.2.3
- WorkManager 2.11.2

## 4. 兼容性、升级建议与已知限制

### 4.1 兼容性

- **中断性变更**：无；`forceUpdate=false`。
- **数据库迁移**：Room v5 -> v6，保留原学期和课程，并建立默认课表。
- **备份兼容**：旧备份继续通过兼容桥接导入默认课表；凭据不进入本地备份或 WebDAV。
- **系统备份**：Android 云备份与设备间直传不作为数据库换机路径。

### 4.2 升级建议

1. 升级前在旧版本中导出一份本地应用备份，并确认文件可以正常读取。
2. 直接覆盖安装，不要卸载旧版本，也不要清除应用数据。
3. 首次启动可能执行数据库迁移与加密转换，请等待其完成，不要强制结束应用。
4. 若进入恢复页，请优先选择刚导出的本地备份或已验证的 WebDAV 备份；不要在未确认旧数据可放弃时创建空数据库。
5. 升级后检查当前课表、学期、课程数量、Widget、提醒和自动静音设置。

### 4.3 已知限制

- 云端脚本更新依赖网络和可用服务；诊断样本不足时可能仍需人工适配。
- 自愈候选不会自动公开上线，当前至少受样本阈值、候选测试、回归测试和管理员审核控制。
- 服务端脚本 runner 与 Android 端 `script_host.js` 目前是两套受约束实现，尚未合并为同一份共享运行时源码。
- 云端任务依赖模型与服务配置；部分任务状态仍保存在内存中，服务重启时可能需要重新提交。
- 公共脚本下载仍保留 HTTP 兼容端点；签名校验保护完整性，但生产环境仍应优先使用 HTTPS。
- 用户拒绝上传诊断样本时，应用不会在后台绕过同意上传原始页面。
- 未授予精确闹钟权限时，提醒和 Widget 边界刷新可能受系统调度延迟影响。
- 通用 APK 同时包含四种 ABI，体积会高于单 ABI 包；本版本继续保持单 APK 分发策略。
- 自建 HTTP 更新元数据可能被中间网络篡改或重放；节点不可用时客户端会切换 HTTPS 备用源，APK 本体仍须通过完整校验才允许安装。
- QR 离线课表传输、课程统计和 HyperOS 实时状态不属于本版本范围。

## 7. 变更范围

本版本相对 v1.0.5.1 的主要实现分布在：

- `core/data`：Room v6、多课表数据访问、SQLCipher 启动与恢复、脚本同步、诊断样本和事务导入。
- `core/domain`：Profile、导入目标、触发器、脚本与诊断领域契约。
- `feature/import`：解析器兼容性、上传同意、脱敏、QuickJS 隔离运行时和脚本选择。
- `feature/settings`：多课表管理、创建、复制、切换、重命名和删除界面。
- `feature/timetable`：Profile-aware 课程流、触发器对账、提醒、静音恢复与课程通知。
- `feature/widget`：活动课表时间线与事件驱动刷新。
- `app`：数据库恢复入口、启动闸门、系统事件恢复、导航和发布构建门禁。
- `benchmark` / `baselineprofile` / `scripts/qa`：性能基线与发布校验工具。

本说明不把尚未完成的 P2/P3 路线图能力计入 v1.0.6.0，也不把云端脚本机制描述为对所有学校页面变化的自动修复保证。
